# 영어 영상 → 한국어 더빙 mp4

영상 1편을 받아(또는 받아 둔 파일로) 화자별 한국어 음성으로 더빙한다. 2026-10-08~09에 영상 8편(7분~166분)으로 검증한 파이프라인이고, 전부 로컬에서 돌며 유료 API를 쓰지 않는다. 이 스킬은 Claude Code, Codex, Antigravity 어디서나 같은 명령으로 쓰도록 만들었다.

- 결과: `<원본이름> (KO dub).mp4` — 영상 1개, 오디오 1=한국어 더빙(원본을 작게 깔고 한국어가 나올 때 더 줄임, 기본 트랙), 2=원본 영어. **기본으로 "개인 학습용 · 재배포 금지" 워터마크가 화면 모서리(구간마다 가장 덜 붐비는 곳)에 5분마다 8초씩 흐리게 뜬다**(8단계).
- **용도 제한**: 개인 학습용이다. 원본 영상의 저작권은 원저작자에게 있으니, 만든 결과를 공개 업로드·재배포하지 않는다고 사용자에게 한 번 알린다. 사용자가 워터마크를 빼 달라고 분명히 요청했을 때만 `--no-watermark`를 쓴다.
- 영상 길이를 L이라 하면 대략: 전사+화자분리 ≈ 0.2L(GPU), 번역 수 분~15분, 합성 ≈ 0.4~0.5L(CPU), 합치기 5~15분(워터마크로 영상을 다시 인코딩; `--no-watermark`는 복사라 1분 이내). 166분 영상이 총 2시간 15분 걸렸다. 1시간이 넘는 영상은 시작 전에 예상 시간을 사용자에게 알린다. NVIDIA GPU가 없으면 몇 배~수십 배 느리다.

## 명령 실행법 (모든 에이전트 공통)

모든 작업은 하나의 명령줄 도구로 한다. 아래에서 `KODUB`는 이것을 뜻한다.

```
py -3 "<이 스킬 폴더>/scripts/kodub.py"
```

`<이 스킬 폴더>`는 이 SKILL.md가 있는 폴더(에이전트가 스킬 파일 경로를 알고 있다)다. `py`가 없으면 `python3`/`python`을 쓴다. 이 런처는 실제 도구 폴더를 같은 폴더의 `toolkit_path.txt` → 환경변수 `KO_DUB_HOME` → 기본 위치(홈 폴더의 `ko-dub`) 순서로 찾는다. 못 찾으면 도구 폴더가 이 PC에 없는 것이니 아래 "다른 PC로 옮기기"를 따른다.

지켜야 할 규칙 (이유와 함께):
- **셸 문법을 쓰지 않는다.** `&&`, `$(...)`, `VAR=값 명령` 같은 bash 전용 문법은 PowerShell(Codex·Antigravity의 Windows 기본 셸)에서 깨진다. 모든 설정은 옵션(`--prompt`, `--female-f0`)으로 넘기고, 경로는 따옴표로 감싼다. 역슬래시/슬래시 어느 쪽도 된다.
- **오래 걸리는 단계는 `--detach`로 시작한다.** 에이전트의 한 번의 명령 실행 시간 제한(보통 수 분~10분)을 넘기면 작업이 죽을 수 있다. `--detach`는 작업을 분리해 돌리고 바로 돌아온다. 그 뒤 `KODUB status "<WORK>"`로 진행을 보거나 `KODUB wait "<WORK>" <작업이름> --timeout 300`으로 기다린다(제한 시간 안에 안 끝나면 종료코드 3과 "계속 실행 중"을 돌려주니 같은 명령을 다시 실행). 에이전트에 자체 백그라운드 알림 기능이 있으면 써도 된다. 기다리는 동안 사용자에게 진행 상황을 한 줄씩 알린다.
- **종료코드**: 0 성공, 1 실패, 2 사용법·환경 오류, 3 아직 실행 중. 로그의 `torchcodec … dll Traceback` 줄은 매번 나오는 무해한 경고이고 도구가 걸러 준다.
- **작업 폴더 `<WORK>`** 는 도구 폴더 아래 `work_<짧은이름>`(절대경로)이다. 다른 영상의 작업 폴더·결과 파일은 건드리지 않는다. 사용자는 완성 후 원본·결과를 직접 지우거나 옮기는 일이 많다. `mux`는 임시 파일에 만들어 검증한 뒤에만 기존 파일을 교체하니 같은 이름으로 다시 만들어도 안전하고, 파일을 삭제하지는 않는다.

## 단계

### 0. 환경 점검 (영상을 받기 전에 먼저)
`KODUB check` (처음 쓰는 PC면 `KODUB check --net`: Hugging Face 접속과 약관 동의까지 확인). `[없음] 필수`가 하나라도 있으면 더빙을 시작하지 말고 부족한 것을 사용자에게 알린 뒤 설치한다.
- 설치: 도구 폴더의 `setup.ps1`을 실행한다 — `powershell -ExecutionPolicy Bypass -File "<도구 폴더>/setup.ps1"`. 인자 없이 실행하면 점검만 하고 부족한 것을 알려 준다. `-InstallMissing`은 Python 3.12·ffmpeg·node를 winget으로 설치하고 통합 환경(`venv-all`: torch CUDA 또는 CPU + 패키지)을 만든다(수 GB, 10~30분). `-DownloadModels [-WithNLLB]`로 모델을 미리 받을 수 있고, 안 받아도 첫 실행 때 자동으로 받아진다(Supertonic 약 380MB, Whisper 약 3GB, NLLB 약 5GB). **프로그램 설치와 대용량 다운로드는 사용자에게 먼저 알리고 허락을 받은 뒤** 실행한다.
- **자동으로 안 되는 것**: Hugging Face 토큰(화자분리용)과 pyannote 약관 동의는 사용자가 직접 한다. https://huggingface.co/settings/tokens 에서 Read 토큰을 만들고 https://huggingface.co/pyannote/speaker-diarization-community-1 에서 약관에 동의한 뒤, `setup.ps1 -HfToken <토큰>`을 사용자가 직접 실행하게 안내한다. 토큰은 비밀번호와 같으니 채팅에 붙여넣게 하지 않는다.

### 1. 입력 확인
- 유튜브 URL: 받기 전에 정보만 조회해 제목·길이·예상 용량을 사용자에게 알린다 — `KODUB info "<URL>" --height 720`. 사용자가 "받아서 만들어줘"처럼 다운로드를 분명히 요청했으면 그대로 진행하고, 요청이 모호하면 먼저 확인한다. 화질은 사용자가 말한 값(기본 720).
- 로컬 파일: `KODUB probe "<파일>"`로 소리가 있는 mp4 하나인지, 영상(소리 없음)+별도 오디오(weba 등)인지 구분한다. 별도 오디오면 8단계 합치기에서 `--orig-audio`를 쓴다.

### 2. 다운로드 (URL일 때)
`KODUB download "<URL>" --out "<저장폴더>" --name "<안전한 파일명>" --work "<WORK>" --height 720 --detach` 후 `wait`. 제목의 `| ' :` 같은 문자가 파일명 문제를 일으키니 이름을 직접 정한다. 결과는 `<저장폴더>/<파일명>.mp4`. 봇 확인 오류가 나면 도구 폴더의 yt-dlp에 `--cookies-from-browser chrome`이 필요하니 사용자에게 알린다. 끝나면 `KODUB probe`로 높이·길이·오디오 유무를 확인한다.

### 3. 전사 + 화자분리 (GPU)
`KODUB step1 "<영상 또는 오디오 파일>" --work "<WORK>" --prompt "<영상 주제와 고유명사 나열>" --detach` 후 `wait`. `--prompt`는 제목·설명에서 뽑은 제품명·사람 이름·약어를 넣으면 전사 정확도가 크게 오른다. 끝나면 로그 마지막에 화자별 발화 시간과 F0(음높이)가 나온다(faster-whisper large-v3 + pyannote community-1).

### 4. 성별 판정 점검
`KODUB speakers "<WORK>"` — 화자별 발화 시간·F0·성별 판정표가 나온다. 기준은 F0 150Hz(`--female-f0`로 조정). 8편 실측으로 남성은 100~145Hz, 여성은 155~215Hz였다. **135~170Hz 경계 화자**는 `KODUB speakers "<WORK>" --formant SPEAKER_01,SPEAKER_00`으로 F1을 보조 근거로 본다(남성 약 410~530, 여성 약 510~610, 노이즈가 커서 보조일 뿐).
음높이·음색(음향)이 1차 근거이고 이름은 보조 정보로만 쓴다. 판단이 갈리는 화자는 합성 때 `--female-f0`를 조정해 배정하되 **최종 보고에 "불확실"로 명시**한다. 틀리면 해당 화자만 음성을 바꿔 다시 합성하면 된다.

### 4.5 전문용어 고정 (번역 전에, 에이전트가 직접 — 사용자에게 시키지 않는다)
번역기는 전문용어를 일반 단어로 옮긴다(실측: shadow map→"그림자 지도" 11/11, ray traced→"방사선 추적"·"빛깔을 추적" 등 4가지로 흩어짐, deferred shading→"연기 그림자"). 그래서 번역 전에 용어를 표식으로 잠갔다가 정해진 한국어로 되돌린다(도구가 자동으로 함, 조사 받침도 자동 교정). 에이전트가 할 일은 이 영상에 맞는 용어를 용어집(`terms.json`)에 채우는 것뿐이다.
1. `KODUB terms "<WORK>"` — 이미 고정된 용어와, 전사에서 뽑은 후보(반복되는 명사구·고유명사, 횟수와 예문)가 나온다.
2. 후보 중 **그 분야 실무자가 쓰는 전문용어·제품명·기능명만** 골라 한 번에 추가한다: `KODUB glossary add --term "attenuation radius=감쇠 반경" "post process volume=포스트 프로세스 볼륨" "fill light=필 라이트"`.
   - 표기 원칙: 한국 실무자가 실제로 부르는 말. 업계에서 영어 음차를 쓰면 음차(쉐도우 맵, 레이 트레이싱, 셰이더, 머티리얼, 에셋, 씬), 굳은 한국어 번역어가 있으면 그것(강화학습, 역기구학, 반사). 제품·기능 이름은 음차(나나이트, 루멘).
   - 일반 단어(performance, default, option 등)와 사람 이름은 넣지 않는다. 뜻이 여러 개인 일반어(light, sample)는 영상 전체가 그 뜻일 때만.
   - 동사·형용사형은 따로 넣는다(`ray traced`). 복수형·하이픈·대소문자는 자동 처리된다.
3. 확신이 없는 용어는 넣지 않는다(넣지 않으면 기존 번역 그대로일 뿐, 더 나빠지지 않는다). 사용자가 표기를 지정하면 그것을 따른다.
`terms.json`은 모든 영상이 함께 쓰므로 영상마다 쌓인다. 추가한 용어 수와 대표 예를 최종 보고에 적는다.

### 5. 번역 (영 → 한)
`KODUB translate "<WORK>" --detach` 후 `wait` — 기본 `--engine auto`가 구글 번역이 열려 있는지 시험해 열려 있으면 구글(품질이 더 좋다), 막혀 있으면(302/429) 로컬 NLLB를 고른다. NLLB는 모델 로드에 수 분이 걸리고 첫 사용이면 약 5GB를 자동으로 받는다. 구글로 시작했다가 도중에 막혀 `FAILED`가 나오면 `--engine nllb`로 다시 실행한다. 구글은 영상 2편(수천 문장)을 연달아 번역하면 IP가 장시간 막히니, 연속 영상은 한 편씩 간격을 둔다.

### 6. 번역 검사 (필수 — 건너뛰지 않는다)
`KODUB scan "<WORK>"` — 전문용어 고정이 적용된 문장 수와, 번역기가 표식을 지워 잠금 없이 다시 번역한 문장(용어가 원래 오역대로일 수 있음)도 함께 나온다. NLLB는 가끔 같은 구절을 수백 자 반복해(예: "이 200개의 조명들을 고려해야 합니다."×N) 합성음이 수십 초가 되고 싱크가 최대 46초 밀린다. "구절 반복" 의심은 영어 원문을 보고 직접 번역해 `<WORK>/fixes.json`(`{"문장id": "새 번역"}`, UTF-8)을 만든 뒤 `KODUB scan "<WORK>" --apply "<WORK>/fixes.json"`으로 적용한다(교정 전 `units.json.bak_before_fix`로 자동 백업). "미번역(영문 그대로)" 의심은 짧은 추임새면 그대로 두어도 되고, 눈에 띄면 같은 방법으로 교정한다. 합성 뒤 `report`의 최대 밀림이 10초를 넘으면 이 단계가 빠진 것이다.

### 7. 발음 점검 + 합성
**발음 점검**: `KODUB dry "<WORK>"` — 화자→음성 배정과 "남은 영문 토큰"이 나온다. 남은 고유명사·제품명은 `KODUB glossary add "Isaac Sim=아이작 심" "PyTorch=파이토치"`처럼 한글 발음으로 추가하고 `dry`를 반복해 거의 없어질 때까지 줄인다. 이유: 발음 변환(`toSpoken`)이 영문 약어를 철자로 읽어 버리고("NVIDIA"→"엔브이아이디아이에이") 영어 단어는 그대로 남아 TTS가 읽지 못한다.
- 용어는 긴 키가 먼저, 대소문자 무시, 영문 경계 기준으로 매칭된다. 한 글자 키(A, B, D)는 넣지 않는다. `glossary show --grep 단어`로 조회한다.
- **숫자가 붙은 용어(`V2D`, `L40S`, `UE5.8`)는 발음 변환이 숫자를 먼저 한글로 바꿔 깨지므로** 통째로 읽는 법을 넣는다(예: `"UE5.8=언리얼 엔진 오 점 팔"`).
- 전문용어는 4.5단계 `--term`이 1순위다(번역 전에 막는다). `KODUB glossary add --fix "궤도=궤적"`(번역 후 문자열 교체)은 용어가 아닌 단골 오역에만 소량 쓴다.
- 용어집 3종 구분: `terms.json`(`--term`, 영어 용어→한국어 용어, 번역 전) / `ko_fixes.json`(`--fix`, 한국어 오역→바른 표현, 번역 후) / `glossary.json`(옵션 없음, 남은 영문→한글 발음, 합성 직전).

**합성(CPU, 가장 오래 걸림)**: `KODUB synth "<WORK>" [--female-f0 160] --detach` 후 `wait`(또는 `status`). 중간에 죽거나 `ABORTED`면 같은 명령을 다시 실행한다(`tts_cache`로 이어하기). 한국어가 영어보다 길어 문장의 약 20~25%는 1.2배 넘게, 일부는 상한 1.45배까지 빨라진다 — 정상이며 보고에 숫자로 적는다. CPU 합성은 동시에 2개 돌리지 않는다(GPU 작업과는 동시에 돌려도 된다).

### 8. 합치기
`KODUB mux --video "<영상>" --work "<WORK>" --out "<결과.mp4>" [--orig-audio "<별도 오디오>"] --detach` 후 `wait`. 소리 없는 영상+별도 오디오(weba)일 때만 `--orig-audio`를 준다.
- **워터마크(기본 켜짐)**: 문구 "개인 학습용 · 재배포 금지 / Personal study use only"를 작고 반투명하게, 시작 직후(최대 20초 지점)와 이후 `--wm-every 300`초마다 `--wm-dur 8`초씩 띄운다. 시청을 거의 방해하지 않는 수준이다.
  - 위치 `--wm-pos auto`(기본): 표시 구간마다 그 시점 화면을 보고 네 모서리 중 글자·로고·UI가 가장 적고 너무 밝지 않은 곳을 고른다(강연 영상은 화면 구성이 계속 바뀌어 한 모서리 고정이면 제목 배너·타이머와 겹쳤다). 고정하려면 `tr|tl|br|bl|tc|bc`. 고른 결과는 `<WORK>/watermark_plan.json`.
  - 용량: 원본 영상 비트레이트 수준(+10%)으로 다시 인코딩한다(화질 기준만 두면 원본의 2.3배가 됐다). 직접 정하려면 `--video-kbps 1500`.
  - 문구 `--watermark "..."`, 글꼴 `--wm-font <ttf>`(한글 글꼴을 못 찾을 때), 끄기 `--no-watermark`(영상 복사라 빠르고 용량 그대로). NVENC가 되면 GPU, 없으면 libx264. ffmpeg에 drawtext 필터가 없으면 중단하고 알려 준다(전체 빌드 ffmpeg 필요).
- 임시 파일에 만든 뒤 영상 1개+오디오 2개·길이 일치를 확인하고 나서 결과 이름으로 교체하며, `[완료]` 줄이 나와야 성공이다.

### 9. 검증과 보고
- `KODUB report "<WORK>"` — 최대·평균 밀림, 밀림 5초 초과 문장 수, 1.2배 넘게 빨라진 문장 수, 화자→음성 배정.
- `KODUB scan "<WORK>"`을 교정 후 다시 돌려 반복 의심이 없는지 본다.
- `KODUB verify "<WORK>" --n 12 [--ids 교정한문장id,...]` — 표본 문장을 한국어 Whisper로 되받아써서 의도 문장과의 유사도를 잰다(평균 0.9 이상이 정상). 전체를 들어서 확인한 것이 아니면 보고에 그렇게 쓴다.

최종 보고 (한국어, 사실만): 결과 파일 경로·용량·길이 / 스트림 구성 / 화자별 음성·성별(**경계·불확실 화자 명시**) / 번역 엔진(구글 or NLLB)과 반복 교정 개수 / 합성 통계 / 검증 결과(확인한 범위와 안 한 범위) / 남은 문제. 확인하지 않은 것은 "확인 안 함"이라고 쓴다.

## 다른 PC·다른 에이전트로 옮기기

- **키트 만들기**: 도구 폴더에서 `powershell -ExecutionPolicy Bypass -File export_kit.ps1`을 실행하면 바탕화면에 `ko-dub-kit.zip`(스크립트·용어집·발음 변환·스킬, 약 0.1MB)이 생긴다. 작업폴더·가상환경·모델 캐시·`python_paths.json`(PC 전용)은 들어가지 않는다.
- **새 PC 설치**: zip을 풀고 `toolkit\setup.ps1 -InstallMissing -DownloadModels -SetEnv -InstallSkill`을 실행한다. 환경 설치, 모델 미리 받기, `KO_DUB_HOME` 설정, 스킬 설치가 한 번에 된다. Hugging Face 토큰은 사용자가 `-HfToken`으로 직접 넣는다.
- **스킬을 에이전트에 설치/갱신**: 원본은 도구 폴더의 `skill/ko-dub` 하나뿐이다. `py -3 "<도구 폴더>/install_skill.py"`가 설치된 에이전트(Claude Code `~/.claude/skills`, Codex `~/.codex/skills`·`~/.agents/skills`, Antigravity `~/.gemini/config/skills`)에 복사본을 만들고 각 복사본에 도구 폴더 경로(`toolkit_path.txt`)를 기록한다. `--list`로 상태를 본다. 원본을 고쳤으면 다시 실행해 전부 갱신한다.
- 호출 방법: Claude Code는 `/ko-dub`, Codex는 `$ko-dub` 또는 `/skills`, Antigravity는 설명에 맞는 요청이나 스킬 이름 언급. 요청이 설명에 맞으면 에이전트가 알아서 고르기도 한다.

## 긴 영상 위임
1시간이 넘는 영상은 서브에이전트 기능이 있는 에이전트에서 하위 에이전트 1명에게 맡겨도 된다. 브리프에 이 SKILL.md 경로를 읽으라고 쓰고, 영상 URL·화질·결과 이름·`--prompt` 재료·이미 알려진 사실(구글 차단 여부 등)을 넣는다. 파일을 쓰는 일은 한 명만 하게 하고, 진행 보고는 단계별로 받는다.
